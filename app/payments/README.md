# Future payment integration

No payment provider or payment endpoint is implemented yet. When requirements select a provider, keep provider credentials in the deployment secret manager and process payment state on the server. Verify transactions directly with the provider and verify webhook signatures against the raw request body. Persist provider event IDs with a unique constraint and make webhook handling idempotent to prevent duplicate events from repeating state changes. Model transaction states and transitions explicitly, and retain an auditable record of payment events without storing sensitive authentication data. Never accept a Flutter-supplied “paid” status as proof of payment. Do not store raw card numbers or card security codes. This foundation does not claim PCI DSS compliance; obtain the required assessment for the eventual payment flow.
